# Edge test plan — 0.0.12 Repeat Off / All / One

Target: Microsoft Edge + Violentmonkey

## Purpose

Validate the first 0.0.12 build that adds Repeat modes on top of the validated 0.0.11 Shuffle + continuous-playback core.

## Setup

- Enable only `google-drive-folder-player.user.js` version 0.0.12.
- Keep old probe/bridge scripts disabled.
- Refresh Google Drive before testing.
- Use the same mixed MP3/WebM folder used for 0.0.11 unless a very small test folder is more convenient for Repeat All.

## Repeat control cycle

1. Confirm the new button starts at `Repeat: OFF`.
2. Click it once -> `Repeat: ALL`.
3. Click it again -> `Repeat: ONE`.
4. Click it again -> `Repeat: OFF`.
5. Confirm the green playback state and amber queue header show the same Repeat mode.

## Repeat ONE test

1. Scan and start playback with either ordered or shuffled mode.
2. Set `Repeat: ONE`.
3. Seek the current MP3 or WebM close to its natural end.
4. Let it finish without pressing Next.
5. Confirm the same queue item is reopened from the beginning and the queue position does not change.
6. Press `Next now` once and confirm it still skips to the following queue item. Repeat ONE must only affect natural track endings.

## Repeat OFF regression test

1. Set `Repeat: OFF`.
2. Confirm ordinary `Next now` and automatic next-track behavior remain identical to 0.0.11 while not at the queue end.
3. Confirm Shuffle still uses the fixed displayed queue.

## Repeat ALL test

A small 2–3 track Drive folder is the easiest way to validate the queue-end behavior without stepping through a long library.

1. Scan the small folder.
2. Choose Ordered or Shuffle and set `Repeat: ALL`.
3. Start playback and advance to the last queue item.
4. Seek the last item near its end and let it finish naturally.
5. Confirm playback wraps to queue item 1.
6. If Shuffle is active, confirm Repeat All reuses the same displayed shuffled order; it must not reshuffle automatically.
7. From the last queue item, `Next now` should also wrap to queue item 1 when Repeat All is active.

## Expected result

- Repeat cycles `OFF -> ALL -> ONE -> OFF`.
- Repeat ONE restarts the naturally finished current track but manual Next still advances.
- Repeat ALL wraps the current fixed queue from its last item back to item 1.
- Repeat ALL does not regenerate a shuffled queue; a new shuffled order is created only by a new Start.
- Repeat OFF preserves the validated 0.0.11 behavior.
- MP3/WebM end detection, Shuffle, transition reliability, and transition speed remain unchanged.
