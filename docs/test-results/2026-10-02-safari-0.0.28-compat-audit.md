# Safari compatibility audit — 0.0.28 baseline

Date: 2026-10-02
Branch: `dev/safari-compat`
Baseline commit before this documentation-only commit: `16bb613c16a37c1ceed742c6a8ead2d13d7f7c7e`
Frozen Edge baseline: `stable/0.0.28-edge` at the same commit.

## Scope

Audit the mature 0.0.28 userscript before making Safari-specific changes. The objective is to preserve the accepted Edge + Violentmonkey behavior and introduce compatibility code only when Safari evidence requires it.

## Baseline evidence reviewed

- `docs/test-results/2026-10-02-edge-0.0.28-owner-pass.md`
- `docs/test-results/2026-09-20-edge-0.0.28-track-search-test-plan.md`
- current `google-drive-folder-player.user.js` on `dev/safari-compat`

The accepted Edge baseline includes complete 160-track discovery, direct MP3/WebM playback via `drive.usercontent.google.com`, preload, natural auto-next, background playback, ordered/shuffle queues, repeat modes, transport controls, minimized transport, dragging, selectable list, double-click selection, search/filter, and collapsed debug details.

## 1. Likely no Safari-specific code required

The current implementation primarily uses standard browser APIs:

- userscript metadata: `@match`, `@grant none`, `@run-at document-idle`, `@noframes`;
- ordinary DOM queries and mutation-free element creation;
- `URL`, `location`, `Element`, `getComputedStyle`, `getBoundingClientRect`;
- `scrollTop`, `scrollTo`, `requestAnimationFrame`;
- `sessionStorage`;
- `input`, `keydown`, `click`, `dblclick`;
- `String.normalize`, case folding, array/map/set operations;
- standard `HTMLMediaElement` events and state properties;
- Pointer Events / pointer capture for panel dragging.

The code does not use browser-vendor globals, Chromium-only extension APIs, Google Drive API, OAuth, API keys, external servers, or privileged userscript APIs.

## 2. Requires Safari real-device confirmation

These areas depend on WebKit policy, codec support, Google Drive rendering, or background behavior and should be tested rather than inferred:

1. Userscripts injection and mount on `drive.google.com` at `document-idle`.
2. Google Drive DOM discovery and scroll-container detection; confirm the reference folder still yields 160 tracks.
3. Direct media URL authentication from Safari to `drive.usercontent.google.com`.
4. Initial playback gesture policy. Current `playIndex()` waits for media readiness before calling `media.play()`; Safari may enforce transient user activation more strictly.
5. Hidden `<video>` playback for WebM.
6. Actual WebM codec/container compatibility of the user's files.
7. `preload='auto'` effectiveness; it is a browser hint, not a guarantee.
8. Automatic next-track playback without a new user gesture.
9. MP3 -> WebM and WebM -> MP3 handoffs.
10. Background-tab playback, timer throttling, and natural end handling.
11. Next-track preload while another media element is active.
12. Panel dragging with Pointer Events on the target Safari build.
13. Google Drive SPA navigation persistence / remount behavior.

## 3. Confirmed need for compatibility code

None at audit time.

No browser-specific compatibility layer should be added before a Safari failure is reproduced. Candidate adaptations should be introduced only against an observed failing case and kept minimal.

## Highest-risk candidate if Safari playback fails

`playIndex()` currently follows this sequence:

1. create media element and set direct URL;
2. call `load()`;
3. await `canplay` / readiness;
4. call `media.play()`.

If Safari rejects step 4 with `NotAllowedError` because the original click/double-click user activation has expired, a Safari-compatible startup path may be required. Do not change this preemptively because the current sequence is already validated on Edge.

## First Safari validation

No probe and no player code change.

Install the unchanged 0.0.28 script from `dev/safari-compat` in macOS Safari + Userscripts, grant Userscripts access to `drive.google.com`, open or refresh a Google Drive page, and verify only that the player panel mounts and identifies itself as version 0.0.28.

Do not scan or start playback in this first validation. This isolates Userscripts metadata/injection and initial DOM mounting from media-policy and Drive-layout questions.
