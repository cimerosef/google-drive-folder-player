# Edge test plan — 0.0.17 direct MP3 two-track preload

Target: Microsoft Edge + Violentmonkey
Branch: `dev/0.0.17-direct-mp3-preload`
Probe: `probes/mp3-two-track-preload-probe.user.js`

## Purpose

Validate the next architectural step after successful file-ID direct MP3 playback: two independent HTML Audio elements using Drive file IDs and the active `authuser` index, with track B preloaded while track A is playing.

The goal is to measure whether track B can start quickly without any Drive Preview close/open cycle.

## Setup

- Disable the main folder-player script and all other probes.
- Enable only `mp3-two-track-preload-probe.user.js`.
- Refresh the Drive folder.
- Do not open Drive Preview.

## Capture two tracks

1. Single-click MP3 #1 in the Drive list.
2. Click `Assign clicked → A`.
3. Single-click a different MP3.
4. Click `Assign clicked → B`.
5. Confirm the green box shows both filenames and the active `authuser` index.

## Preload test

1. Click `Preload A+B`.
2. Wait until both A and B report `loadedmetadata` / `canplay`.
3. Confirm neither Drive Preview nor any Drive media overlay opens.
4. Confirm B can remain loaded while A is later played.

## Fast manual switch test

1. Click `Play A`.
2. After A is audibly playing, click `Switch now to B`.
3. The log should print `A→B audible-start latency: ... ms` when B fires `playing`.
4. Note whether the switch feels substantially faster than the old Preview-based transition.

## Natural end test

1. Make sure `Auto A→B: ON`.
2. Start A.
3. Click `Seek A to last 5s`.
4. Do not touch anything else; let A end naturally.
5. Expected: the `ended` event immediately requests `B.play()` and B becomes audible.
6. The log should show the A→B audible-start latency.

## Background test

1. Repeat the natural-end test.
2. After seeking A to the last 5 seconds, immediately switch to another browser tab.
3. Let A finish while Drive is hidden.
4. Expected: B starts without needing the Drive page to become visible and without any Drive Preview UI transition.

## Pass criteria

- Both tracks load directly from file IDs with no Preview.
- B remains ready while A plays.
- Manual and natural A→B transitions both work.
- Background A→B transition works.
- No duplicate playback and no Drive Preview appears.
- Transition latency is dramatically lower than the prior Preview close/open path.

## Scope

This is MP3-only. WebM remains deliberately out of scope until direct MP3 queue behavior is proven stable.
