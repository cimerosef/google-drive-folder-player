# Edge + Violentmonkey — 0.0.28 track-search test plan

Date: 2026-09-20

## Goal

Add a lightweight live search box above the scanned track list without changing the accepted direct-playback and transport behavior.

## Intended behavior

- after a folder has been scanned, a `Search tracks…` field appears above the complete track list;
- filtering happens live while typing;
- search is case-insensitive and accent-insensitive;
- filtering affects only what is visible in the list: it does not alter the playback queue or its order;
- the heading shows the number of matches, for example `8/160 tracks`;
- double-clicking a filtered result starts that exact track;
- the currently playing track remains highlighted whenever it matches the active search;
- the clear `×` button restores the complete list;
- Escape while the search field is active also clears the query;
- Previous / Pause-Resume / Next, Shuffle, Repeat, minimize/restore, background playback and direct MP3/WebM playback remain unchanged.

## Regression checks

1. Refresh Drive with only the 0.0.28 userscript enabled.
2. Scan the reference Music folder and confirm 160 tracks are still discovered.
3. Type part of a song title and confirm the list filters immediately and the match count changes.
4. Search using different capitalization and, where applicable, an accented/unaccented spelling.
5. Double-click a filtered MP3 result and confirm the exact track starts.
6. Double-click a filtered WebM result and confirm the exact track starts.
7. Confirm clearing with `×` restores all 160 tracks.
8. Confirm Escape also clears the query.
9. While a search is active, use Previous / Pause-Resume / Next and confirm the queue itself is not shortened to the search results.
10. Minimize the player and confirm compact transport controls continue to work.

## Non-goal

0.0.28 does not add fuzzy matching, phonetic/transliteration search, tags, artist metadata, or persistent playlists.
