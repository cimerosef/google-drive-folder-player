# Safari + Userscripts — 0.0.35 inactive cached-media quarantine test plan

Date: 2026-10-18

## Goal

Preserve the 0.0.33 immediate previous-track cache while preventing any cached/preloaded non-current media element from becoming independently audible.

## Owner finding

0.0.34 fixed the intermittent auto-playback stop, but an earlier/previous track could sometimes become audible at the same time as the intended current track and was not controlled by the visible player transport.

The exact external trigger was not reproduced deterministically.

## 0.0.35 containment

All non-current media slots are now treated as quarantined:

- newly created `next` preload slots start muted;
- `previous` and reused `next` cache slots are paused, reset and muted;
- promotion to `current` explicitly unmutes the selected slot;
- before a new current starts, the old current is muted and paused;
- after transition, cached previous/next slots are defensively kept muted and paused;
- if any slot that is not `directCurrent` fires a `playing` event, it is immediately muted and paused.

Diagnostic if Safari/browser reactivates an inactive slot:

`Blocked unexpected playback from inactive ... slot`

## Preserved behavior

- previous-track instant cache remains enabled;
- normal next preload remains enabled;
- 0.0.34 fresh retry for stalled promoted media remains enabled;
- Media Session controls/metadata remain enabled;
- discovery/scanning is unchanged.

## Static verification

- JavaScript syntax: PASS.

- previous cache present.
- stalled-preload fresh retry present.
- inactive-slot playing guard present.
- Media Session integration present.

## Safari acceptance test

Primary validation is ordinary real-world playback.

1. Update Userscripts to 0.0.35 and refresh Google Drive.
2. Start playback and let several tracks advance naturally in the background.
3. Use Next and Previous a few times, including rapid back-and-forth navigation.
4. Confirm only one audible track exists at all times.
5. Confirm Previous still returns smoothly from cache.
6. Confirm playback no longer stops on the earlier stalled-preload condition.
7. If any ghost playback attempt occurs, inspect Debug for:
   `Blocked unexpected playback from inactive ... slot`

If the diagnostic appears but no second track becomes audible, the containment is working as designed.
