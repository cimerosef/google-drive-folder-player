# Safari + Userscripts — 0.0.30 Media Session system routing FAIL

Date: 2026-10-17

## Environment

- macOS Safari
- Userscripts
- Branch: `dev/safari-compat`
- Player version: `0.0.30`

## Owner observation

While the Google Drive Folder Player was actively playing audio:

- macOS Now Playing showed a generic Safari media session;
- the displayed system item did not show the current Google Drive track metadata;
- the system controls showed 15-second seek backward / forward actions rather than Previous Track / Next Track;
- Mac keyboard media keys did not control the Google Drive Folder Player.

The in-page player itself continued playing normally.

## Assessment

FAIL for the new 0.0.30 Media Session acceptance criteria.

Safari is clearly publishing the underlying HTML media playback to macOS, but the custom Media Session metadata/action layer is not currently taking ownership of the system session as intended.

This does not yet identify whether the cause is:

- Media Session handlers/metadata not being registered successfully in the Userscripts execution environment;
- registration being overwritten after setup;
- Safari associating the active system media session with the underlying HTMLMediaElement default session rather than the scripted Media Session state;
- another Safari/WebKit routing constraint.

## Next diagnostic

Before changing the playback engine, inspect the player's existing Debug details while playback is active.

Expected initialization log from 0.0.30:

`Media Session ready: 4/4 action handler(s) registered.`

Also verify whether a metadata-update failure is logged.

No compatibility workaround should be introduced until this distinction is established.
