# Safari + Userscripts — 0.0.30 Media Session registration PASS, system routing mismatch

Date: 2026-10-17

## Owner evidence

The player Debug log shows:

`Media Session ready: 4/4 action handler(s) registered.`

No `Media Session metadata update failed` message is present.

During the same playback session:

- current Google Drive MP3 metadata duration: 269 seconds;
- preloaded next MP3 metadata duration: 188 seconds.

The macOS Now Playing panel shown by the owner instead displayed a generic Safari session with approximately 12 seconds remaining.

## Conclusion

The 0.0.30 JavaScript registration path is working:

- Media Session API exists;
- all four action handlers register without exception;
- metadata assignment does not report failure.

However, the system Now Playing panel is not currently representing either the active Google Drive media element or its preloaded next element.

The duration mismatch is direct evidence that macOS/Safari has selected another Safari media session for system controls.

## Next diagnostic

Perform an isolated Safari-session test before changing code:

1. close or pause every other Safari tab/window that may contain audio/video;
2. leave only the Google Drive player tab active;
3. start one known track;
4. open macOS Now Playing;
5. verify whether its duration/title now match the Google Drive track;
6. test Play/Pause and Next media keys.

No player-code change is justified until this isolation test is complete.
