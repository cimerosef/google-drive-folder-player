# Edge test plan — 0.0.11 shuffled queue

Target: Microsoft Edge + Violentmonkey

## Purpose

Validate the first 0.0.11 build that adds a shuffled playback queue on top of the validated 0.0.10 continuous-playback core.

## Setup

- Enable only `google-drive-folder-player.user.js` version 0.0.11.
- Disable old WebM probe/bridge scripts.
- Refresh Google Drive before testing.
- Use the same mixed MP3/WebM folder used for the 0.0.10 validation.

## Main shuffle test

1. Click `Scan folder view` and confirm the usual cached media count.
2. Click `Shuffle: OFF` once; it should become `Shuffle: ON`.
3. Confirm the amber queue box shows `Queue SHUFFLE` and a visibly randomized list.
4. Click `Start continuous test`.
5. Confirm the opened first track matches item 1 in the displayed shuffled queue.
6. Click `Next now` several times and confirm each opened track follows items 2, 3, 4, etc. in the displayed shuffled queue rather than Drive folder order.
7. Let one MP3 or WebM track reach its natural end (seeking close to the end is fine) and confirm automatic advance follows the next item in the same shuffled queue.
8. Confirm MP3/WebM progress detection and transition speed remain comparable to 0.0.10.

## Queue stability test

- While playback is active, toggle Shuffle OFF or ON once.
- The current queue must stay unchanged; the panel should say the new setting applies on the next Start.
- `Next now` must continue following the already displayed queue.

## New-shuffle test

1. Stop playback.
2. Leave Shuffle ON.
3. Click `Start continuous test` again.
4. Confirm a new shuffled queue is generated. It may occasionally share individual positions by chance, but the overall order should normally differ.

## Ordered regression test

1. Stop playback.
2. Set `Shuffle: OFF`.
3. Start again.
4. Confirm the queue returns to Drive folder order and ordinary continuous playback still works.

## Expected result

- Shuffle uses a Fisher–Yates queue built from the currently cached media items.
- Each cached item appears once in a queue; no repeat is introduced by Shuffle itself.
- Manual Next and automatic end-of-track advance follow the same fixed queue.
- Changing the Shuffle toggle during active playback does not mutate the current queue; it applies on the next Start.
- Repeat remains intentionally out of scope for 0.0.11.
