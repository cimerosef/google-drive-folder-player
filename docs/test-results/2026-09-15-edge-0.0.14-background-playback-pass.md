# Edge background playback validation — 0.0.14

Target: Microsoft Edge + Violentmonkey

## Result

User tested the 0.0.14 guarded background-transition build for roughly ten or more consecutive tracks while using other browser tabs.

Observed result: background playback continued across track boundaries without reproducing the 0.0.13 failure where playback stopped after one or two tracks.

The Background Playback Probe showed multiple successful natural end detections and automatic transitions across both ordinary visible-slider audio items and WebM/video items using the hidden native range signal.

Examples captured in the validation run included transitions 11 -> 12, 12 -> 13, and 13 -> 14 while the Drive tab changed between hidden and visible states.

## Interpretation

The narrow 0.0.14 change appears to fix the diagnosed background close-confirmation failure without breaking the existing end detector.

This is strong practical evidence that the guarded hidden-tab transition path is working. Keep the result as validated for the tested Edge + Violentmonkey environment, while retaining 0.0.13 as the previous stable baseline until 0.0.14 is formally promoted.

## Follow-up observation

The user also reported that track-to-track playback is not perceptually seamless: the next Drive preview is only opened after the current track ends, so the load/open action is noticeable. This is a separate transition-latency / next-track warm-up optimization and should be handled independently from the background reliability fix.
