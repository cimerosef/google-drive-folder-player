# Safari + Userscripts — 0.0.31 Media Session resynchronization test plan

Date: 2026-10-17

## Evidence from 0.0.30

The owner demonstrated that macOS media-key commands can reach the player intermittently:

- Debug recorded `via direct media (Next)`;
- Debug recorded `via direct media (Previous)`.

Therefore the Media Session command path is viable.

However:

- macOS Now Playing never showed the current track title;
- the displayed progress was stale / frozen;
- keyboard control became unreliable after initially working.

## 0.0.31 approach

Keep the accepted direct-media/preload architecture unchanged and strengthen only the Media Session synchronization layer.

Changes:

- assign current-track MediaMetadata before `play()` so Safari has metadata when playback claims the system session;
- reassert metadata on the current media element's `loadedmetadata` and `playing` events;
- re-register the four Media Session handlers when a new current track starts;
- use `MediaSession.setPositionState()` with duration/currentTime/playbackRate;
- force position sync at metadata load, play and pause;
- refresh position state from `timeupdate`, throttled to approximately every 4.5 seconds;
- preserve existing direct playback, preload, scan and queue behavior.

## Static verification

- JavaScript syntax: PASS.
- No change to direct media URL generation.
- No change to preload selection or natural-next sequencing.
- No change to folder discovery logic.

## Safari acceptance test

1. Update Userscripts to 0.0.31 and refresh Google Drive.
2. Start one track.
3. Open macOS Now Playing.
4. Verify whether the track title now appears.
5. Leave Now Playing open for at least 10–15 seconds and verify the progress advances.
6. Test Play/Pause, Next and Previous.
7. Put the Google Drive tab/window in the background and repeat Play/Pause + Next.

Record separately:
- metadata display;
- live progress;
- media-key stability.
