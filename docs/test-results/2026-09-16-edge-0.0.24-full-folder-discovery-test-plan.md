# Edge + Violentmonkey — 0.0.24 full-folder discovery test plan

Date: 2026-09-16

## Goal

Validate a discovery-only approach for traversing Google Drive's virtualized file list and accumulating MP3/WebM rows beyond the currently rendered batch.

The validated 0.0.23 player is intentionally untouched.

## Setup

1. Keep `stable/0.0.23` / the 0.0.23 main player disabled for this test.
2. Enable only `probes/full-folder-discovery-probe.user.js` from `dev/0.0.24-full-folder-discovery`.
3. Refresh the Drive Music folder.
4. Confirm the probe title is `Full Folder Discovery Probe 0.0.1`.

## Test A — automatic traversal

1. Start somewhere in the Music folder; the list does not need to be at the top.
2. Click `Discover full folder` once.
3. Do not manually scroll while it runs.
4. Watch whether the Drive list automatically moves from the top toward the bottom.

Expected:

- the probe identifies a Drive list scroll container.
- the unique count should grow beyond the initial rendered batch if more files exist.
- overlapping virtualized rows are deduplicated by stable Drive ID.
- the log shows step-by-step `top/currentRange`, rendered count, newly added count and cumulative unique count.
- the probe stops after a stable bottom pass and returns near the original scroll position.

## Test B — result quality

At completion, inspect the green summary and the first/last names in the amber list.

Expected:

- MP3 and WebM counts add up to the total unique count.
- obvious duplicates should not appear.
- the first and last discovered names should correspond plausibly to the folder's current sort order.
- no Drive Preview opens and no file is modified.

## Test C — manual stop

Optional: start another discovery and click `Stop` midway.

Expected:

- it exits after the current sample.
- already discovered results remain visible.
- the list returns near its original scroll position.

## What to send back

A screenshot of the final probe panel is enough. The most useful lines are:

- the detected `Scroller:` line;
- a few intermediate `Step ... unique=...` lines;
- `Bottom settle:`;
- the final `Discovery completed: ...` line.

If the count stays around 50, that is also useful: it would mean the chosen scroll container or Drive loading behavior needs a second probe iteration.

## Non-goal

This probe does not feed the discovered full-folder list into the player yet. Integration into the 0.0.23 player will happen only after discovery itself is validated.
