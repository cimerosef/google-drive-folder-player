# Safari + Userscripts — 0.0.30 Media Session test plan

Date: 2026-10-17

## Goal

Add standard Media Session integration without changing the accepted direct-playback core.

Target behavior:

- macOS system media UI shows the currently playing track;
- Mac media Play/Pause key controls the player;
- Mac Previous Track key calls the existing previous-track behavior;
- Mac Next Track key calls the existing next-track behavior;
- controls continue to work with the Google Drive tab in the background;
- unsupported Media Session APIs fail open and do not affect ordinary in-page controls.

## Implementation

0.0.30 adds a small compatibility layer around the existing player:

- guarded detection with `'mediaSession' in navigator`;
- `MediaMetadata` with:
  - title = current filename without `.mp3` / `.webm`;
  - artist = `Google Drive`;
  - album = `Google Drive Folder Player`;
- Media Session action handlers:
  - `play`;
  - `pause`;
  - `previoustrack`;
  - `nexttrack`;
- `navigator.mediaSession.playbackState` synchronization;
- metadata/session clearing when playback is stopped or the queue finishes.

The handlers reuse the existing `togglePause()`, `previousNow()`, and `nextNow()` paths. No separate playback engine was introduced.

## Static verification

- JavaScript syntax check: PASS.
- Existing direct-media URL generation unchanged.
- Existing preload / auto-next functions unchanged apart from Media Session state synchronization.
- Existing discovery logic unchanged from 0.0.29.

## Safari acceptance test

1. Update Userscripts to 0.0.30 and refresh Google Drive.
2. Scan the Music folder and start any track.
3. Open macOS system media / Now Playing and confirm the current song title is shown.
4. Press the Mac Play/Pause media key: confirm pause, then press again and confirm resume.
5. Press Next Track: confirm the next queue track starts.
6. Press Previous Track: confirm the previous queue track starts.
7. Repeat at least Play/Pause + Next while the Google Drive tab is in the background.

If the Mac has another active media application/session, close or pause it for the first isolated test so routing ambiguity does not mask the browser result.

## Edge follow-up

After Safari PASS, perform a short Edge + Violentmonkey regression for Media Session plus the still-pending shared 0.0.29 discovery regression.
