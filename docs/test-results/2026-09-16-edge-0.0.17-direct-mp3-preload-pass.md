# Edge validation — 0.0.17 direct MP3 preload PASS

Platform: Microsoft Edge + Violentmonkey
Date: 2026-09-16

## Result

The direct-MP3 two-track preload experiment passed in both foreground and background conditions.

Validated sequence:

- Two different MP3 Drive rows were captured by stable Drive ID.
- Both tracks loaded through direct `drive.usercontent.google.com/download` URLs using `confirm=t` and the current Drive `authuser` index.
- Both A and B reached `canplay` before transition testing.
- A played in the probe without any Google Drive Preview UI.
- A was seeked to its last ~5 seconds.
- On A `ended`, the probe immediately called `B.play()`.
- B started smoothly with no perceptible long Drive Preview transition.
- The same A→B transition was repeated after the Drive tab had been moved to the background before A ended.
- B still started automatically and continued normal playback while Drive remained in the background.

## Conclusion

Direct MP3 playback is viable without Drive Preview once the script has the file's stable Drive ID and the correct Drive account slot (`authuser`). Preloading the next direct Audio element removes the previous preview-close/open bottleneck and remains functional in a background tab.

This validates moving the next development stage toward a direct-MP3 playback core while preserving the existing Preview-based path as fallback for formats not yet validated (notably WebM).
