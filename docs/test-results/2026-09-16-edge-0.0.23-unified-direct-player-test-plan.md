# Edge + Violentmonkey — 0.0.23 unified direct player test plan

Date: 2026-09-16

## Goal

Validate the first full-player integration of the unified Direct Media Core.

Validated foundations already inherited:

- MP3 direct playback by Drive ID + `drive.usercontent` URL.
- WebM direct playback by the same route.
- one-track preload for both formats.
- foreground and background MP3/WebM handoff.
- dynamic promotion fix from Direct Media Core Probe 0.0.2.
- Shuffle, Repeat and draggable main panel from the earlier player.

0.0.23 intentionally does **not** solve full-folder discovery yet.

## Setup

1. Enable only `google-drive-folder-player.user.js` from `dev/0.0.23-unified-direct-player`.
2. Disable the standalone Direct Media Core / MP3 / WebM probes and older main-player builds.
3. Refresh the Google Drive Music folder.
4. Click `Scan folder view`.
5. Confirm the panel title reports `Probe 0.0.23`.

## Test A — basic mixed direct playback

Start with Shuffle OFF if convenient and exercise the following boundaries using `Next now` and/or `Seek last 5s`:

- MP3 -> MP3
- MP3 -> WebM
- WebM -> MP3
- WebM -> WebM

Expected:

- MP3 and WebM never open Google Drive Preview.
- status reports `Engine: DIRECT MP3` or `Engine: DIRECT WEBM`.
- the next direct track reaches `next preloaded` whenever possible.
- natural transitions continue after a preloaded slot is promoted.
- transition log reports small direct audible-start latency.

## Test B — Shuffle

1. Stop playback.
2. Turn Shuffle ON.
3. Start the direct player.
4. Use several `Next now` actions and at least two natural endings.

Expected:

- queue order is randomized once at Start.
- queue order remains stable during playback.
- direct MP3/WebM preload still follows the shuffled order.

## Test C — Repeat ONE

1. Set Repeat ONE while a direct MP3 is playing.
2. Use `Seek last 5s` and let it finish naturally.
3. Confirm the same track restarts.
4. Click `Next now` and confirm it still advances.
5. Repeat the same check on a direct WebM.

Expected:

- natural end repeats the same media element from the beginning.
- `Next now` ignores Repeat ONE and advances normally.

## Test D — Repeat ALL

Use a short queue position near the end if convenient, or manually advance near queue end.

Expected:

- queue wraps to item 1 without rebuilding Shuffle order.
- if item 1 is MP3/WebM, it returns through the direct engine.

## Test E — background playback

While a direct track is playing and the panel shows `next preloaded`:

1. use `Seek last 5s`.
2. immediately switch to another browser tab.
3. stay away from Drive until the next track should already have started.
4. repeat once across MP3 -> WebM and once across WebM -> MP3 if possible.

Expected:

- the next track starts in the background.
- no Drive Preview appears.
- no old multi-second/long background Preview-transition delay returns.

## Test F — fallback smoke test (only if another supported non-MP3/WebM format is visible)

For formats such as M4A/MP4/etc., the build retains the old Drive Preview fallback.

Expected:

- fallback format may open Drive Preview.
- after that track, a following MP3/WebM can return to direct playback.

This fallback smoke test is optional if the folder contains only MP3/WebM.

## Known non-goal

The visible/cached item count can still be lower than the real folder total because Google Drive virtualizes its file list. Do not treat that as a 0.0.23 failure.
