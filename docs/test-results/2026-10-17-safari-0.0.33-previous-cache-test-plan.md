# Safari + Userscripts — 0.0.33 immediate previous-track cache test plan

Date: 2026-10-17

## Goal

Reduce the visible reload delay when the user presses Previous.

Existing behavior:

- the next track is preloaded;
- Previous normally creates a fresh media element and may show a short reload delay.

0.0.33 adds one bounded previous-track cache.

## Design

When playback advances by exactly one queue position:

- do not dispose the old current media element;
- pause it, reset it to the beginning, and retain it as `directPrevious`;
- keep only one previous cached element.

When Previous targets that cached item:

- promote `directPrevious` directly to current;
- avoid creating/loading a fresh media element.

When navigating backward by one:

- the former current track is reused as `directNext`;
- this allows a quick forward return as well.

For arbitrary queue jumps, stale previous cache is discarded.

No additional previous-track network preload is introduced.

## Resource / compatibility constraints

- at most three media elements may exist transiently: previous cache, current, next preload;
- previous cache is paused;
- direct URL generation is unchanged;
- scan/discovery code is unchanged;
- Media Session handlers/metadata behavior from 0.0.32 is unchanged;
- only one immediate previous item is cached.

## Static verification

- JavaScript syntax: PASS.
- version: 0.0.33.
- previous-cache promotion path present.
- forward transition stores old current as previous cache.
- backward transition reuses old current as next cache.

## Safari acceptance test

1. Update Userscripts to 0.0.33 and refresh Google Drive.
2. Start a track and use Next once.
3. After the new track begins, press Previous.
4. Compare the transition with 0.0.32:
   - expected: previous track starts almost immediately, without the obvious fresh-load wait.
5. Press Next again:
   - expected: quick return to the track just left.
6. Confirm normal automatic next still works.
7. Confirm Mac media Play/Pause / Previous / Next controls still work from another application.

The macOS Now Playing progress-bar limitation remains accepted and is not part of this test.
