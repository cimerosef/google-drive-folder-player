# Edge + Violentmonkey — 0.0.36 scan reliability + UI redesign test plan

Date: 2026-11-22
Branch: `dev/0.0.36-scan-reliability-ui` (based on `dev/safari-compat` 0.0.35)

## Problem being fixed

Occasionally a first scan of the 172-track Music folder stopped at 150 tracks; a second scan found all 172.

Root cause: Drive appends folder rows in batches of 50. When the scan reached the bottom of the list it waited a fixed 650 ms for more rows. If Drive's next batch took longer (slow network or a busy Drive), the scan declared the folder complete at 150 (three full batches). On a second scan every row was already loaded, so it always succeeded.

A mock Drive page (`dev/mock-drive/index.html`) reproduces this: with 0.9–1.8 s batch delays, 0.0.35 returned 172, 97 and 172 on three cold first scans.

## What changed in the scan

- Each scroll step waits for Drive's list to stop changing (MutationObserver) instead of a fixed 360 ms.
- **Coverage guard:** the scan never scrolls past the lowest row it has actually seen, so late rendering cannot create gaps.
- **Bottom patience:** at the bottom the scan keeps nudging Drive's infinite-scroll trigger for 3 s, extended to 12 s while a loading indicator is visible.
- **Batch-boundary check:** if the list ends on an exact multiple of 50 rows, or on fewer tracks than the last scan of this folder, the scan waits up to 8 s more before finishing.
- Nudging never jumps to a bottom that grew mid-nudge (that would skip a whole batch).
- Scan results are cached per folder in `localStorage`, so reopening Drive shows the library instantly. Rescanning is only needed when files change.

Mock results for 0.0.36 (cold first scan, cache cleared each time): 172/172 in every scenario. Scenarios tested: 0.1–0.4 s, 0.9–1.8 s, 1.5–2.9 s and 3–6 s batch delays, with and without a loading indicator; 250/400 ms render lag; a non-virtualized list; a folder of exactly 150; a folder of 30.

## What changed in the UI

- One Play/Pause button: it starts the queue (scanning first if needed), pauses and resumes. The separate Start/Stop buttons are gone; Stop is in Diagnostics.
- Standard transport row: Shuffle · Previous · Play/Pause · Next · Repeat (Repeat-one shows a "1" icon).
- Seekable progress bar with elapsed/total time.
- Shuffle now applies immediately, re-shuffling the upcoming tracks around the current one. Toggling it off returns to folder order.
- Previous restarts the track if more than 3 s in (common player behaviour).
- Rescan is allowed during playback; the queue is rebuilt around the playing track.
- Track list: hover ▶ button or double-click to play, Enter in search plays the first match, a locate button jumps to the current track, an animated equalizer marks the playing row. Unavailable tracks are struck through.
- Auto-advance skips up to 3 consecutive tracks that fail to load (e.g. a file deleted since the cached scan).
- Shuffle/Repeat and panel position are remembered.
- The panel follows Drive's light/dark theme.
- Minimized view: title, thin progress line, Previous/Play/Next, Expand.
- Folder awareness: the library follows the open Drive folder while idle. While playing, it keeps the current library and offers "Scan this" for the newly opened folder.

## Real-Drive checks (Edge + Violentmonkey)

1. Fresh Drive tab, open the Music folder, press **Scan** (or Play). Expected: 172 tracks.
2. Repeat step 1 in three fresh tabs, ideally once with network throttling (DevTools → Slow 4G). Expected: 172 each time. Diagnostics log should show `Bottom grew…`/`Bottom confirmed…` lines.
3. Reload Drive: library shows 172 immediately with "scanned … ago".
4. Play, Pause, Resume, Next, Previous (early and after 3 s), seek by clicking the progress bar.
5. Toggle Shuffle during playback: current track keeps playing; list order changes; natural end advances to the next row shown. Toggle off: folder order with the current track highlighted.
6. Repeat off/all/one cycle; "Jump to last 5 s" in Diagnostics confirms natural end behaviour in each mode.
7. Minimize / expand; drag the panel; reload and confirm position and minimized state persist.
8. Drive light and dark themes.
9. System media keys / Now Playing still work (Media Session unchanged).
10. Background tab playback across a track change (unchanged core; regression check).
