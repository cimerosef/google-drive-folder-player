# Edge + Violentmonkey — 0.0.26 minimize + pause test plan

Date: 2026-09-16

## Goal

Extend the cleaned-up player shell with two everyday-use controls without changing the validated discovery/direct-playback core:

- minimize/restore the player so it does not obstruct unrelated Google Drive documents;
- pause/resume the current track without losing position or rebuilding the queue.

## Intended UI behavior

- full player keeps the 0.0.25 compact layout;
- top-right `−` minimizes the panel;
- minimized view becomes a small `♪ Google Drive Player` bar;
- `▢` restores the full player;
- minimized state is remembered for the current browser tab through `sessionStorage`;
- full view has a `Pause` button that becomes `Resume` while paused;
- minimized view also exposes a small pause/resume button (`Ⅱ` / `▶`) so playback can be controlled without restoring the full panel;
- pausing keeps the exact playback position, current queue, preload and Shuffle/Repeat settings;
- resuming continues the same track from the paused position;
- `Stop` remains different from Pause: Stop disposes the current media/preload, whereas Pause preserves them;
- scanning remains blocked while a current track is playing or paused, avoiding a rescan while the current queue is active.

## Regression checks

1. Refresh Drive with only the 0.0.26 main userscript enabled.
2. Confirm the full player mounts and can still be dragged.
3. Run `Scan folder`; reference folder should still return 160 tracks (144 MP3 + 16 WebM).
4. Start playback and pause mid-track. Confirm audio stops immediately and the button changes to `Resume`.
5. Wait a few seconds, resume, and confirm the same track continues from the same position.
6. Repeat Pause/Resume once on an MP3 and once on a WebM track.
7. Minimize while playing. Confirm the panel collapses to the small bar and playback continues.
8. Use the minimized `Ⅱ` button to pause, then `▶` to resume without restoring the panel.
9. Restore with `▢` and confirm the full state/queue is unchanged.
10. Exercise Next, Shuffle and Repeat after a pause/resume cycle.
11. Confirm at least one background handoff still works.
12. Expand `Debug details` and confirm logs are still collected.

## Non-goal

No changes to full-folder discovery, direct media URLs, preload strategy, Shuffle, Repeat or background handoff algorithms.
