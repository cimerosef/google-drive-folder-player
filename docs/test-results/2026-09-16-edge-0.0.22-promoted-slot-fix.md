# Edge + Violentmonkey — direct media core promoted-slot bug

Date: 2026-09-16

## Observed failure

Direct Media Core Probe 0.0.1 successfully played track 1 (MP3), preloaded and promoted track 2 (WebM), and preloaded track 3 (MP3). When track 2 ended naturally, playback stopped instead of advancing to track 3.

The log showed the promoted track still reporting events with the `next` role, including its final `ended` event.

## Root cause

In 0.0.1, event handlers captured the slot role (`current` or `next`) at creation time. A preloaded `next` slot kept that captured role after promotion to current playback. The natural-end handler only advanced when the captured role was `current`, so a promoted track could finish without triggering the next transition.

This is format-independent: it could affect a promoted MP3 as well as a promoted WebM.

## Fix in probe 0.0.2

- Store role as mutable slot state.
- Change the role to `current` on promotion.
- Make event logging read the live slot role.
- Trigger natural-end advancement from actual current-slot identity rather than the original creation role.
- Measure audible-start latency from actual current-slot identity as well.

## Retest

Re-run the same mixed queue path, especially:

1. MP3 -> WebM -> MP3 by natural end.
2. WebM -> MP3 -> WebM by natural end.
3. Repeat with `Next now` mixed in.
4. If foreground passes, repeat one mixed transition with Drive in a background tab.

Expected: every promoted preloaded track should continue to the following track regardless of MP3/WebM type.
