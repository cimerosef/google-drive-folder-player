# Edge test plan — 0.0.14 background transition recovery

Target: Microsoft Edge + Violentmonkey

## Purpose

Validate the narrow 0.0.14 fix for the failure observed when Google Drive is playing in a background tab.

The 0.0.13 diagnostic proved that end-of-track detection still worked while the tab was hidden, but the automatic transition aborted because preview closure was not confirmed in time. 0.0.14 changes only that failure path.

## Setup

- Enable `google-drive-folder-player.user.js` version 0.0.14 from `dev/0.0.14-background-playback`.
- Keep `probes/background-playback-probe.user.js` version 0.0.2 enabled for diagnostics during this validation.
- Disable the old 0.0.13 main player so only one main player is active.
- Refresh Google Drive.
- Use the same mixed MP3/WebM folder used in previous tests.

## Primary background test

1. Scan the folder and start continuous playback.
2. Shuffle and Repeat may be set as normally used; Repeat ALL is suitable for a long unattended run.
3. While the first track is playing, switch to another browser tab and keep using the browser normally.
4. Do not return to the Drive tab at the first track boundary.
5. Let at least 3–5 tracks finish naturally if playback continues.
6. Return to Drive only after several transitions, or immediately if playback stops.

## Expected guarded-path behavior

If Drive delays preview-close confirmation while the tab is hidden, the main diagnostic may show messages similar to:

- `Close confirmation timed out while hidden; continuing only with positive target-title confirmation.`
- `Open attempt ... [guarded background]`
- `Transition accepted ... Guarded background path confirmed by target title.`

The old fatal message `Transition blocked: Drive ignored the scripted close-button click.` must no longer terminate playback merely because close confirmation was delayed in a hidden tab.

A guarded background transition is accepted only when the requested next track's exact preview title is positively confirmed. Progress-only evidence is intentionally insufficient on this recovery path.

## Foreground regression check

After the background run:

1. Keep the Drive tab visible.
2. Press `Next now` several times.
3. Confirm foreground transition speed and reliability remain comparable to 0.0.13.
4. Confirm Shuffle, Repeat ONE, Repeat ALL, WebM progress detection, and draggable-panel behavior remain unchanged.

## Failure evidence

If background playback still stops:

- Do not refresh the Drive tab.
- Do not press `Next now` first.
- Capture the Background Playback Probe log and the main 0.0.14 diagnostic panel.

Those logs should distinguish a row-resolution failure, target-preview confirmation failure, or another Drive background behavior from the already diagnosed close-confirmation timeout.
