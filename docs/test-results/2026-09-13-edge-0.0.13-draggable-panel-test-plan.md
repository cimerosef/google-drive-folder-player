# Edge test plan — 0.0.13 draggable panel

Target: Microsoft Edge + Violentmonkey

## Purpose

Validate the first 0.0.13 build that makes the player panel movable without changing the validated 0.0.12 playback, Shuffle, or Repeat behavior.

## Setup

- Enable only `google-drive-folder-player.user.js` version 0.0.13.
- Refresh Google Drive before testing.
- Use the same mixed MP3/WebM folder used for the previous validations.

## Dragging test

1. Confirm the panel still opens at its normal bottom-right position after refresh.
2. Move the mouse over the title `Google Drive Folder Player — Probe 0.0.13`; the cursor should indicate that the title is draggable.
3. Hold the left mouse button on the title and drag the panel to another area of the page.
4. Confirm the whole panel follows smoothly and stays where it is released.
5. Drag toward all four viewport edges and confirm the panel is clamped inside the browser viewport rather than disappearing off-screen.
6. Confirm buttons, queue scrolling, and the panel's own scrollbar still work normally and do not start a drag.

## Playback regression test

1. Scan the folder and start playback after moving the panel away from Drive's media controls.
2. Confirm `Next now` remains responsive.
3. Confirm Shuffle still follows the displayed queue.
4. Confirm Repeat ONE and Repeat ALL controls still cycle and behave normally.
5. For a WebM item, confirm hidden native range progress detection still appears as before.

## Refresh behavior

1. Move the panel away from the bottom-right corner.
2. Refresh Google Drive.
3. Confirm the panel intentionally returns to its default bottom-right position. Position persistence is not part of 0.0.13.

## Expected result

- Only the title bar acts as the drag handle.
- Dragging does not interfere with buttons, queue scrolling, Drive playback, or media progress controls.
- The panel cannot be dragged completely outside the viewport.
- Refresh resets the panel to its default bottom-right position.
- No playback logic or userscript permissions change; the script remains `@grant none`.
