# Safari + Userscripts — 0.0.34 stalled promoted-media recovery test plan

Date: 2026-10-18

## Goal

Prevent an unattended queue from stopping when a preloaded/cached media element becomes unusable before promotion.

## 0.0.33 failure mode

Observed sequence:

- current track ends naturally;
- preloaded next slot is promoted;
- promoted slot never becomes ready;
- `playIndex()` returns false;
- auto-advance chain stops.

## 0.0.34 recovery

The normal successful preload path is unchanged.

Only when a promoted slot fails readiness:

1. log that the promoted slot is unavailable;
2. dispose that slot;
3. create a fresh current media element for the same target track;
4. wait with the ordinary fresh-load timeout;
5. continue playback if ready.

Expected diagnostic when recovery is actually needed:

`Promoted preload slot unavailable ...; retrying with fresh media.`

followed by:

`Fresh retry ready ...`

If the fresh retry also fails:

- report `Track could not be loaded after retry`;
- stop auto mode only when the previous current track has already ended;
- clear the system media session in that stopped state;
- refresh playback/queue/transport UI so it does not appear to remain actively playing.

## Scope

Unchanged:

- direct URL construction;
- next-track preload behavior in the healthy path;
- previous-cache behavior;
- Media Session controls/metadata;
- discovery/scanning;
- shuffle/repeat semantics.

## Static verification

JavaScript syntax: PASS.

## Owner validation

Primary real-world acceptance:

- update to 0.0.34;
- allow ordinary background playback to continue across multiple natural transitions;
- confirm the queue no longer stops at a stalled promoted slot.

If the fallback is triggered, capture the two recovery log lines above.

A normal 6 -> 7 transition without triggering the fallback is still a PASS for ordinary playback, but longer unattended playback provides stronger resilience evidence because the original failure was intermittent.
