# Edge + Violentmonkey — 0.0.20 WebM direct-play test plan

Date: 2026-09-16

## Goal

Determine whether a Google Drive `.webm` file can use the same no-Preview direct playback architecture already validated for MP3.

The probe uses:

`https://drive.usercontent.google.com/download?id=<Drive ID>&export=download&confirm=t&authuser=<current account index>`

with a detached HTMLVideoElement and `preload=auto`.

## Setup

1. Keep `stable/0.0.19` as the playback baseline.
2. Disable the 0.0.19 main player and all older probes for this isolated test.
3. Enable only `probes/webm-direct-play-probe.user.js` from `dev/0.0.20-webm-direct-probe`.
4. Refresh the Drive Music folder.
5. Do not open Drive Preview.

## Test

1. Single-click one visible `.webm` row.
2. Confirm the probe logs `Remembered WebM snapshot ... stable id captured.`
3. Click `Capture clicked WebM`.
4. Click `Load direct WebM`.
5. Wait for events.

Strong success evidence:

- `loadedmetadata`
- `loadeddata`
- `canplay`
- finite duration
- no `errorCode=4`

6. If `canplay` appears, click `Play direct WebM`.
7. Confirm audio/video playback starts without Google Drive Preview.
8. Optionally click `Seek to last 5s` and confirm the media reaches `ended` normally.

## Interpretation

### PASS

If direct WebM reaches `canplay` and `play()` succeeds without Drive Preview, WebM can likely join the same direct preload architecture as MP3.

### FAIL / needs deeper probe

If the direct URL produces `errorCode=4`, HTML/redirect content, or otherwise cannot decode, the next investigation should inspect the exact Preview-delivered WebM source/stream rather than guessing URL parameters.

## Non-goals

This test does not modify the 0.0.19 main player, Shuffle/Repeat, or full-folder discovery.
