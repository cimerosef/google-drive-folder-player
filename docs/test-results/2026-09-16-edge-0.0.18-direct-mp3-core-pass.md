# Edge + Violentmonkey — 0.0.18 Direct MP3 Core Probe PASS

Date: 2026-09-16
Platform: Microsoft Edge + Violentmonkey
Branch: `dev/0.0.18-direct-mp3-core`
Probe: `probes/direct-mp3-core-probe.user.js`

## Result

PASS for the direct MP3 queue core on the currently visible Drive rows.

Validated manually:

- Scan found 43 currently visible MP3 rows with stable Drive IDs.
- Queue started without opening Google Drive Preview.
- Direct MP3 playback used `drive.usercontent.google.com/download` with `confirm=t` and the current Drive `authuser` index.
- The next MP3 was preloaded while the current MP3 was playing.
- Natural track end promoted the already-preloaded next Audio element smoothly.
- `Next now` transitions were smooth.
- Seeking the current track to the final ~5 seconds and letting it end produced smooth automatic transitions.
- Five to six consecutive tracks were exercised successfully.
- No Drive Preview appeared during the tested direct-MP3 queue path.

## Known limitation observed in this test

The probe scanned only 43 MP3s because it intentionally scans only Drive rows currently rendered/visible in the virtualized folder view. This is a separate full-folder discovery problem and is not considered a failure of the direct MP3 playback core.

## Conclusion

The direct MP3 engine is ready for the next integration stage. Full-folder discovery should remain a separate later milestone so playback-core changes and Drive virtualization changes are not mixed in the same iteration.
